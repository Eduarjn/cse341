# Week 02 Specification: Books and Authors

Extends the Week 01 read-only Books API with:

- a related `authors` collection,
- write routes (create, update, delete) for books and authors,
- Swagger documentation and testing at `/api-docs`.

Database: `cse341-books-db` (MongoDB Atlas). MongoDB's internal `_id` is never returned by the API.

## 1. Data models

### Author (`authors` collection)

| Field | Type | Rules |
| --- | --- | --- |
| `id` | string | Generated by the server: `a` + next number (`a1`, `a2`, ...). Unique. Cannot be changed. |
| `name` | string | Required. 1 to 100 characters after trimming spaces. |
| `nationality` | string | Optional. Up to 60 characters. |

```json
{ "id": "a1", "name": "Maya Rivera", "nationality": "American" }
```

### Book (`books` collection)

| Field | Type | Rules |
| --- | --- | --- |
| `id` | string | Generated by the server: `b` + next number (`b1`, `b2`, ...). Unique. Cannot be changed. |
| `title` | string | Required. 1 to 200 characters after trimming spaces. |
| `authorId` | string | Required. Must be the `id` of an existing author. |
| `publicationDate` | string | Required. ISO 8601 date `YYYY-MM-DD` that exists on the calendar. |

```json
{ "id": "b1", "title": "Patterns of Light", "authorId": "a1", "publicationDate": "2021-08-17" }
```

**Change from Week 01:** the free-text `author` field is replaced by `authorId`, a reference to an
author document. The author's name now lives in one place, so renaming an author updates every
book.

## 2. Relationship between books and authors

- **One to many:** one author has many books; each book has exactly one author, through
  `books.authorId` → `authors.id`.
- **Unknown author:** creating or updating a book with an `authorId` that does not exist is
  rejected with **400**.
- **Author with books:** deleting an author who still has books is rejected with **409 Conflict**
  and nothing is deleted. Delete or reassign those books first, so no book points to a missing
  author.
- **Books of an author:** `GET /authors/:id/books` lists the books of one author.

## 3. Routes

| Method | Path | Success | Errors |
| --- | --- | --- | --- |
| GET | `/books` | 200, array of books | 500 |
| GET | `/books/:id` | 200, one book | 404, 500 |
| POST | `/books` | 201, created book + `Location` header | 400, 500 |
| PUT | `/books/:id` | 200, updated book | 400, 404, 500 |
| DELETE | `/books/:id` | 204, no body | 404, 500 |
| GET | `/authors` | 200, array of authors | 500 |
| GET | `/authors/:id` | 200, one author | 404, 500 |
| GET | `/authors/:id/books` | 200, array of books by that author | 404, 500 |
| POST | `/authors` | 201, created author + `Location` header | 400, 500 |
| PUT | `/authors/:id` | 200, updated author | 400, 404, 500 |
| DELETE | `/authors/:id` | 204, no body | 404, 409, 500 |
| GET | `/api-docs` | Swagger UI | |

Rules for request bodies:

- **POST and PUT** take the editable fields: `name` and `nationality` for authors; `title`,
  `authorId` and `publicationDate` for books.
- **PUT is a full update:** every required field must be sent.
- **Ignored fields:** an `id` in the body is ignored (the id comes from the URL or the server), and
  so are unknown fields.
- **Text fields** are trimmed before they are saved.
- **Lists** are sorted by the number in the `id` (`a2` before `a10`).

## 4. Response bodies

| Case | Status | Body |
| --- | --- | --- |
| Success with data | 200 / 201 | the book or author object, or an array of them |
| Validation failed | 400 | `{ "message": "Validation failed", "errors": ["title is required", "..."] }` |
| Body is not valid JSON | 400 | `{ "message": "Invalid JSON body" }` |
| Not found | 404 | `{ "message": "Book not found" }` or `{ "message": "Author not found" }` |
| Author still has books | 409 | `{ "message": "Author has books; delete or reassign them first", "bookIds": ["b1"] }` |
| Unexpected error | 500 | `{ "message": "Internal server error" }` (details only in the server log) |

## 5. Status code decisions

- **201 Created for POST, not 200.** A new resource exists after the request, and the `Location`
  header gives its URL (`/books/b4`).
- **200 with the updated object for PUT, not 204.** The client (and Swagger) sees exactly what was
  saved, including trimmed values.
- **204 No Content for DELETE.** Nothing is left to return.
- **400 for an `authorId` that does not exist, not 404.** The URL was found; the problem is a value
  in the body the client sent. 404 is reserved for the resource in the URL.
- **409 Conflict for deleting an author who still has books, not 400.** The request is
  well-formed and the author exists, but it conflicts with the current state of the data. It
  works once the books are gone.

## 6. Swagger

- **Document:** an OpenAPI 3.0 file (`swagger.json`) served with `swagger-ui-express` at
  `/api-docs`.
- **Server URL:** relative (`/`), so the same document works locally and on Render.
- **Coverage:** every route documents its path parameters, request body schema with an example,
  and every response code above.

## 7. Seed data

- **Files:**
  - `scripts/authors.seed.json`: authors `a1` to `a3`.
  - `scripts/books.seed.json`: books `b1` to `b3`, now with `authorId` instead of `author`.
- **Script:** `npm run seed` upserts both files into the database configured in `.env`, which
  also converts the Week 01 books to the new model.

## 8. Testing

- **Local:**
  - Swagger at `http://localhost:3000/api-docs`.
  - Automated tests: `npm test`, with `node:test` and an in-memory MongoDB.
- **Deployed:** `https://cse341-books-api-qe83.onrender.com/api-docs`. Every route is tried
  through Swagger after the deploy.
